## Payload

Remove this section when the app uses a registered provider without a change.

Give the payload as a template. Write one placeholder for each field that the skill completes.

```json
{
  "aps": { "alert": "<ALERT TEXT>", "sound": "default", "badge": 1 },
  "<KEY>": "<DEEP LINK>"
}
```

| Field       | Required | Value                  |
| ----------- | -------- | ---------------------- |
| `aps.alert` | Yes      | The text of the banner |
| `<KEY>`     | Yes      | The deep link URL      |

Mark a field as required when the app opens no screen without that field. The skill asks for a required field that it cannot infer. The skill does not ask about the other fields.

State which component claims the message, and state what the app does with the URL. A developer who reads only this file must understand the function of each key.

## Test data

Give the test data that a link needs. State also how to get a new value.

The skill cannot invent a valid id or token. An invented value opens the screen, and the screen then fails to load its data. The developer sees the symptom of a routing defect. Name the seeded account, the fixture record, or the command that makes a token.
